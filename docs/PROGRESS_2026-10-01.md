## 2. Commit 1：`071f644` — Add AMR hardware BOM and safety requirements

這個 commit 建立了 AMR 硬體架構的第一份基線文件（`docs/HARDWARE_BOM.md`），涵蓋：

- **系統架構**：Jetson Orin Nano Super 負責 ROS 2 與高階運算，透過 `cmd_vel` 下達指令給低階 MCU；MCU 負責 PWM/方向輸出與編碼器（Encoder）讀取。
- **底盤幾何**：2WD 差速驅動（已實測：輪徑 70 mm、輪半徑 35 mm、輪距 130 mm、Ø12 mm 滾珠腳輪）。
- **馬達與編碼器**：N20 / GA12-N20 減速馬達（候選規格，尚未最終確認），要求必須是「已內建編碼器」版本，並明確規定不可假設特定極數或計數值（如 14 poles、8344 counts）為已知事實。
- **雙 H-Bridge 馬達驅動器**：MCU → PWM/DIR → 雙 H-Bridge → 左右 N20 馬達，並要求明確定義 boot/reset/通訊中斷時的安全關閉狀態。
- **電源架構**：區分馬達電源軌與邏輯電源軌，要求保護與去耦設計。
- **低階控制器（MCU）**：負責確定性（deterministic）編碼器擷取與低階馬達輸出，Jetson 不直接驅動馬達、也不負責逐筆計數編碼器脈波。
- **IMU 需求**：三軸陀螺儀＋加速度計為必要項目，磁力計僅列為選用（Optional），且不可視為可靠的方向真值。
- **角色分工**：明確劃分 ROS 2（高階整合）、LabVIEW（儀控／驗證，非馬達安全控制）、Holoscan／MONAI（未來擴充，非驅動控制）的責任邊界。

**仍維持 TBD / UNKNOWN、尚未選定的項目**（不可視為已完成）：
- 編碼器 PPR / CPR、每輪轉實際計數值
- 實際 N20 馬達型號與齒輪比（298:1 為候選值）
- MCU 型號、IMU 型號、相機型號
- H-Bridge 型號、電池規格
- 命令逾時時間（command timeout）、最大速度／加速度限制
- 實際煞車減速度（braking deceleration）

## 3. Commit 2：`bd68947` — Refine AMR hardware BOM with sensing reference

這個 commit 補強了編碼器／位置回授（Position Feedback）相關的感測技術參考：

- 在「磁性漸增式編碼器（Magnetic Incremental Encoder）」這個功能性需求之下，新增了一種具體的候選感測技術：**磁阻感測（Magnetoresistive Sensing, AMR / GMR / GMI）**。

> ⚠️ **命名澄清**：這裡的 **AMR** 指的是「**各向異性磁阻**（Anisotropic Magnetoresistance）」這項感測技術，與本專案的 **AMR（Autonomous Mobile Robot，自主移動機器人）** 是兩個完全不同、但剛好同縮寫的名詞，請勿混淆。

- 磁阻感測技術透過坡莫合金（Permalloy）薄膜電阻隨磁場變化的特性運作，具備高頻率響應（最高可達約 5000 kHz），適合高速、高精度的馬達回授與定位應用。
- **這只是一種 sensing reference／candidate technology（候選技術）**，用來說明「磁性漸增式編碼器」這個需求底下有哪些實作方式可以評估，**並不代表實際編碼器型號已經選定** —— 實際 IC 與規格仍維持 BOM 表格中的 TBD 狀態。

## 4. Commit 3：`11e0b20` — Add AMR safety calibration and stopping-distance reference

這個 commit 同時新增三份文件／程式：`SAFETY_AND_COLLISION_AVOIDANCE.md`、`CALIBRATION_PLAN.md`、`dynamic_safety_field_reference.py`。

### A. 安全架構（Safety Architecture）

分為四層：

| 層級 | 內容 |
|---|---|
| **Physical Safety（物理安全）** | 實體緊急停止（E-stop）、H-Bridge 的 ENABLE/STBY/SLEEP 硬體關閉路徑、選用型碰撞開關／近場感測、馬達電源隔離 |
| **Low-level Safety（低階安全）** | MCU 指令看門狗（Watchdog）、過期指令偵測、boot/reset/通訊中斷時馬達輸出強制關閉、編碼器合理性檢查、感測器健康監控 |
| **Robotics Software（機器人軟體層）** | 預期指令（desired cmd_vel）→ **安全監督器（Safety Supervisor）** → 安全指令（safe cmd_vel）→ MCU 馬達控制器 |
| **Perception（感知層）** | 立體／RGB-D 障礙物偵測、選用型近場感測器、未來感測器融合 |

並定義了安全監督器（Safety Supervisor）的四種狀態：

- **NORMAL**：障礙物在安全區域外、指令有效、必要感測器健康 → 允許正常速度
- **SLOW**：障礙物進入減速警戒區 → 平滑降低指令速度
- **STOP**：障礙物進入關鍵停止區 → 線速度／角速度收斂至零
- **FAULT**：指令過期、通訊中斷、感測器資料無效、安全輸入觸發、控制器錯誤 → 馬達輸出必須進入安全狀態

文件中也明確指出：**ROS 2 並非唯一的安全機制**，MCU／低階硬體必須在指令過期或主機斷線時，獨立地讓馬達停止。

### B. 校準計畫（Calibration Plan）

涵蓋六大類校準項目：

1. **底盤校準（Drivetrain Calibration）**：以「轉動剛好 10 圈、量測編碼器增量」的方式推算每輪轉實際計數值，並需左右輪、正反轉分別驗證。
2. **相機內參校準（Camera Intrinsic Calibration）**：fx、fy、cx、cy、畸變係數（相機型號尚未選定）。
3. **立體／RGB-D 外參校準（Stereo/RGB-D Extrinsic Calibration）**：相機間轉換關係、基線、旋轉、平移。
4. **相機對 IMU 外參校準（Camera-to-IMU Calibration）**：旋轉、平移與剛性安裝要求。
5. **IMU 偏差／比例校準（IMU Bias / Scale Calibration）**：陀螺儀偏差、加速度計偏差、刻度、軸向，並明確指出不可假設磁力計方向在靠近馬達／金屬結構時可靠。
6. **時間同步校準（Temporal Synchronization）**：堅持「量測擷取時間戳記 ≠ 主機接收時間戳記」原則，並列出 ROS 2 `message_filters`（近似時間同步器）作為候選軟體對齊機制。

### C. 煞停距離演算法參考（Stopping-distance Algorithm Reference）

`research/dynamic_safety_field_reference.py` 實作了以下工程參考模型：

```text
反應距離（reaction distance）
+
煞車距離（braking distance）
+
不確定性餘裕（uncertainty margin）
=
最小煞停距離（minimum stopping distance）
```

並依此距離分類出 NORMAL / SLOW / STOP 三種狀態。此程式已通過編譯測試（`py_compile`）與自我測試（self-tests，涵蓋零速度、STOP／SLOW／NORMAL 區間分類、速度與延遲對煞停距離的影響、無效煞車減速度拋出錯誤等案例），並附帶明確標示為「DEMO ONLY — NOT AMR CALIBRATION VALUES」的範例數值。

> ⚠️ 文件與程式中都明確標註：**「工程參考模型（Engineering Reference Model），不是安全認證公式」**。本原型目前並未通過任何工業安全認證（如 ISO 10218、ANSI/RIA R15.06、CE），N20 驅動系統也沒有機械式故障安全（Fail-safe）煞車機制，這些標準被列為「未來合規目標」（Future Compliance Targets），而非已達成項目。

## 7. 下一個 Milestone 建議

**「Safety Supervisor ROS2 Reference Node」**

概念流程：

```text
/cmd_vel
   ↓
Safety Supervisor
   ↓
/cmd_vel_safe
   ↓
MCU
```

下一階段的目標，是把今天已經在文件與離線演算法參考（offline algorithm reference）中定義好的 NORMAL / SLOW / STOP / FAULT 判斷邏輯，逐步實作成一個真正的 ROS 2 reference node：接收 `/cmd_vel`、依據障礙物距離與今天建立的煞停距離模型計算安全狀態，輸出經過限制或攔截的 `/cmd_vel_safe` 給 MCU。此節點初期仍會是「reference / 參考實作」性質，並持續沿用「不自行發明最終校準數值」的原則，待硬體選型與校準完成後再逐步收斂為正式版本。
